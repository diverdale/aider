1) Quick Start (Recommended)

Follow this order for a clean first experience:

  1. Run /health and fix any failed checks.
  2. Set UI defaults: ui-density, ui-layout, and ui-progress-strip.
  3. Try the palette with Ctrl-P and choose a command number.
  4. If you use reusable workflows, install and enable skills.
  5. Apply a color theme preset, then override individual colors as needed.
If something feels off, run /health --quick to re-check local configuration quickly.

2) Skills Overview

Aider can now discover and use SKILL.md files from:

  • ~/.aider/skills (global)
  • ./.aider/skills (project local)

Skills can be triggered in two ways:

  • Automatic: Aider matches your prompt against a skill trigger list.
  • Explicit: invoke it directly with /skill-name.
Trigger matching is lowercase substring matching. Longest matching trigger wins.

3) Skills Commands

Use /skills to manage installed skills:

CommandPurpose
/skills or /skills listList skills with state and metadata.
/skills refreshRescan skill directories.
/skills info <name>Show details for one skill.
/skills load <url-or-path>Install from local path, raw URL, or GitHub URL.
/skills remove <name>Delete installed skill directory.
/skills enable <name>Enable skill (removes .disabled marker).
/skills disable <name>Disable skill (creates .disabled marker).
/skills update <name>Reinstall from stored source in .source.

4) Skills Step-by-Step

Install from GitHub and run immediately:

1) /skills load https://github.com/org/repo/blob/main/skills/review/SKILL.md
2) /skills list
3) /review "review these changed files"
4) /skills update review   # later, refresh from saved source

Local skill authoring:

Create a directory like ~/.aider/skills/tdd-helper and place SKILL.md:

---
name: tdd-helper
description: Guide strict red-green-refactor loop for coding tasks.
version: "1.0"
triggers:
  - test driven
  - write tests first
  - tdd
---

# TDD Helper

When invoked, produce failing tests first, then minimal code, then refactor.

Invoke explicitly with /tdd-helper or rely on auto trigger matching.

5) Color Theme Features

The color system adds:

  • color-theme: choose a preset or a custom theme file path
  • rule-color: control divider color independently
  • --color-theme list: print available presets
  • Override precedence: explicit color values win over theme defaults
Theme values apply first, then explicit per-color settings override them.

6) Theme Step-by-Step

Most reliable workflow:

1) Set a preset:
   color-theme: iterm-dark

2) Override only what you need:
   assistant-output-color: "#ff8800"
   rule-color: "#7aa2f7"

3) Restart aider and verify visually.

Show preset names

aider --color-theme list

Preset with local overrides

color-theme: iterm-dark
assistant-output-color: "#ff8800"
rule-color: "#7aa2f7"
code-theme: github-dark

Custom theme file

color-theme: /home/user/.aider/themes/my-theme.yml
assistant-output-color: "#ffaa00"

8) UI Settings Guide

These settings work as CLI flags or config keys:

SettingValuesPurpose
ui-densitycompact, comfortable, focusControls terminal density and verbosity.
ui-layoutsingle, split, review-firstApplies layout-specific framing and hints.
ui-key-hintstrue/falseShows prompt footer shortcut hints.
ui-progress-striptrue/falseShows Now/Next/Waiting footer status.

9) Layout Presets (Explicit Behavior)

single: default behavior with no layout-specific guidance.

split: grouped readonly/editable context messaging plus split cues.

review-first: emphasizes review flow with /diff and /undo guidance.

# CLI examples
aider --ui-layout single
aider --ui-layout split
aider --ui-layout review-first
Current split/review-first modes are behavior presets, not full pane managers.

10) Command Palette (Non-Intuitive Bits)

Primary flow:

1) Press Ctrl-P (or type /palette tok)
2) Review numbered matches
3) Enter a number when prompted
4) Selected action runs immediately

Important details:

  • Ctrl-P reuses current input as query text when helpful.
  • If current input is /tokens, palette query becomes tokens.
  • Press Enter at selection prompt to cancel without running anything.
# direct usage
/palette
/palette tok
/palette 1

11) Healthcheck (First-Run and Debugging)

Run diagnostics:

/health
/health --quick

Current checks include:

  • API key presence for active model
  • Model/provider reachability (skipped in --quick)
  • Git readiness

Output provides PASS/WARN/FAIL and a fix line when applicable.

12) Complete Config Example

color-theme: iterm-dark
rule-color: "#7aa2f7"

ui-density: compact
ui-layout: review-first
ui-key-hints: true
ui-key-hints-template: "{model} | ctx {context_pct} | {mode}"
ui-progress-strip: true
ui-progress-template: "Now:{now} Next:{next} Waiting:{waiting_on}"

13) Troubleshooting

  • If /skill-name is not found, run /skills refresh.
  • If a skill does not auto-apply, verify it has non-empty triggers.
  • If Ctrl-P feels off, try /palette directly to isolate prompt-keybinding issues.
  • If palette ranking feels wrong, use a more specific query (for example: /palette health).
  • If /health connectivity fails, rerun /health --quick to isolate local config vs network/provider issues.
  • If colors look unchanged, check whether explicit color keys are overriding the theme.
  • If using explicit --config, ensure expected settings are in that exact file.
With explicit --config, default config discovery/merge is intentionally bypassed.
